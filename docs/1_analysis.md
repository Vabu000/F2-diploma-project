## 1.3 Аналіз та порівняння існуючих рішень

Таблиця 1.1 – Порівняльна інженерна матриця систем управління ресурсами
| Критерій | Poster POS | Square for Restaurants | Odoo ERP | Проєктована система |
| :--- | :--- | :--- | :--- | :--- |
| **Архітектура** | Моноліт | Мікросервіси | Трирівневий моноліт | Модульний моноліт (State Machine) |

**Аналітичний висновок підрозділу 1.2**
Проаналізовано існуючі програмні рішення та виявлено, що використання класичних монолітних структур або синхронних REST-запитів у системах Poster та Odoo провокує затримки (Latency) при масовому перерахунку залишків. Архітектури аналогів не забезпечують достатньої пропускної здатності для динамічного трекінгу станів продукції у реальному часі без суттєвих інфраструктурних витрат.

Обраний технологічний стек (React, Node.js, PostgreSQL) та патерн модульного моноліту з інтеграцією State Machine успішно вирішують виявлені проблеми. Реалізація ізольованої бізнес-логіки транзакційного списання дозволяє знизити навантаження на базу даних та забезпечити високу швидкодію системи без необхідності розгортання дорогої мікросервісної інфраструктури, що є оптимальним для обраної предметної області.
